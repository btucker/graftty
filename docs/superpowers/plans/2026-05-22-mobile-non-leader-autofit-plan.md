# Mobile Non-Leader Auto-Fit — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the iPhone fullscreen horizontal-scroll fallback (`IOS-5.6`) and the iPad split-view scroll fallback (`IPAD-2.5`) with font-fit-to-`serverCols` when GrafttyMobile is not the size-leader; add pinch and long-press as new leadership-claim triggers alongside the existing keystroke claim; document and fix the PTY width-on-reattach drift the user observed on Mac.

**Architecture:** `TerminalWidthLayout.decide` changes return type from `.fits / .scrollable(frameWidth:)` to `.useConfigFont / .fitFont(pointSize:)`. The math mirrors `PanePreviewFontSizing`. The fullscreen view applies the override via `controller.updateConfigSource(.generated(appendingFontSizeOverride(...)))` — the same path pane previews already use. Three claim triggers (keystroke, pinch, long-press), all routed through the existing `SessionClient.claimLeadershipIfNeeded()`. Once leader, the layout decision is no longer driven from outside; libghostty's pinch is in charge. The Mac-side detach bug is fixed by suppressing redundant `HostManagedZmxBackend.receiveResize` calls that would shrink the PTY before the surface has been measured against its real `NSView` bounds after a re-attach.

**Tech Stack:** Swift 6, Swift Testing, SwiftUI, UIKit, libghostty-spm, zmx.

**Spec:** `docs/superpowers/specs/2026-05-22-mobile-non-leader-autofit-design.md`

```swift
#if canImport(UIKit)
import CoreGraphics

/// Pure decision: given the iOS container's width, the server-announced
/// grid width (may be nil before the first `grid` control frame), the
/// configured (iOS-scaled) font size from `GhosttyConfigFetcher`, and
/// whether the iOS client has claimed size-leadership, should the
/// terminal pane render at the configured font or under a font-size
/// override sized so `serverCols × cellWidth ≤ containerWidth`?
///
/// Mirrors the math in `PanePreviewFontSizing` so previews and the
/// fullscreen not-leader path use the same fit logic.
public enum TerminalWidthLayout {
    static let monospaceAspect: CGFloat = 0.6
    static let safetyScale: CGFloat = 0.95
    static let minimumFontSize: Float = 2

    public enum Decision: Equatable {
        /// Use the base iOS-scaled config font. Caller treats this as
        /// "ensure the override (if any) is removed" while not-leader,
        /// or "leave whatever is applied alone" once leader.
        case useConfigFont
        /// Apply this font size as an override on the terminal
        /// controller so that `serverCols × cellWidth ≤ containerWidth`.
        case fitFont(pointSize: Float)
    }

    public static func decide(
        containerWidth: CGFloat,
        serverCols: UInt16?,
        configFontSize: Float,
        isLeader: Bool
    ) -> Decision {
        if isLeader { return .useConfigFont }
        guard let serverCols, serverCols > 0, containerWidth > 0 else {
            return .useConfigFont
        }
        let targetCellWidth = (containerWidth / CGFloat(serverCols)) * safetyScale
        let targetFontSize = Float(targetCellWidth / monospaceAspect)
        if targetFontSize >= configFontSize {
            return .useConfigFont
        }
        return .fitFont(pointSize: max(minimumFontSize, targetFontSize))
    }
}
#endif
```

```swift
    controller: TerminalController,
    containerSize: CGSize
) -> some View {
    let pane = TerminalPaneView(
        session: client.session,
        controller: controller,
        focusRequestCount: focusRequestCount,
        softwareKeyboardInput: .init(

            }

    )
    pane

            )
        }

private struct FontFitKey: Hashable {
    let containerWidth: CGFloat
    let serverCols: UInt16?
    let isLeader: Bool
    let baseConfig: String?
}

private func reconcileFontOverride(
    client: SessionClient,
    controller: TerminalController,
    containerWidth: CGFloat
) {
    // Freeze-on-claim (IOS-6.10): once leader, stop driving the font.
    guard !client.isSizeLeader else { return }
    guard let baseConfig = baseConfigText else { return }
    let configSize = GhosttyConfigFetcher.lastFontSize(in: baseConfig)
        .map { Float($0) }
        ?? Float(GhosttyConfigFetcher.defaultMacFontSize * GhosttyConfigFetcher.iosFontScale)

    let decision = TerminalWidthLayout.decide(
        containerWidth: containerWidth,
        serverCols: client.serverGrid?.cols,
        configFontSize: configSize,
        isLeader: false
    )
    switch decision {
    case .useConfigFont:
        guard liveFontOverride != nil else { return }
        controller.updateConfigSource(.generated(baseConfig))
        liveFontOverride = nil
    case let .fitFont(pointSize):
        if liveFontOverride == pointSize { return }
        let overridden = MobileTerminalControllerFactory.appendingFontSizeOverride(
            to: baseConfig,
            fontSize: pointSize,
            comment: "GrafttyMobile auto-fit — non-leader"
        )
        controller.updateConfigSource(.generated(overridden))
        liveFontOverride = pointSize
    }
}
```

## Task 7: PTY width persistence on Mac re-attach (IOS-12.1)

The Mac client unconditionally forwards every libghostty resize callback (`HostManagedZmxBackend.receiveResize` at `Sources/Graftty/Terminal/HostManagedZmxBackend.swift:217`) to the zmx session. On re-attach, the first viewport callback fires before the surface has been measured against its real `NSView` bounds — producing a small `(cols, rows)` that shrinks the PTY.

The fix is the Mac mirror of IOS-6.5: do not call `currentSession?.resize(...)` for the first post-attach viewport callback when no user input has occurred since attach. The very first user-input event (keystroke, mouse-click that produces a chord, etc.) lifts the gate.

This task contains a small investigation step before the fix, because the offending callback site may live deeper than the surface (libghostty internals call back through `receiveResizeCallback`).
