# Maintain Width on LRU Re-attach — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve a hibernated worktree's terminal column count across the LRU evict / re-attach cycle so that re-selecting an evicted worktree does not reflow its scrollback at the macOS-default 80×24 PTY winsize.

**Architecture:** `TerminalManager.evictSurface` captures the live surface's `ghostty_surface_size_s` (cols, rows, pixel width, pixel height) before tearing down the libghostty surface, keyed by `PaneSlotID`. On the next `createSurface` / `createSurfaces` for that pane, the cached size is consumed once and threaded into the new `SurfaceHandle.init` via a new `initialGridSize:` parameter, which (1) plumbs `(cols, rows)` to `HostManagedZmxBackend`'s session factory so the outer `zmx attach` PTY is born at the right winsize, and (2) calls `ghostty_surface_set_size` on the new libghostty surface to the cached pixel dimensions before `backend.start()` runs.

**Tech Stack:** Swift 5.10, libghostty C API (`ghostty_surface_size`, `ghostty_surface_set_size`), Swift Testing (`@Suite` / `@Test`), the existing `SurfaceHandleTestHarness` / `FakeSurfaceHandleZmxBackend` / `FakeHostManagedSession` test doubles.

**Spec:** `docs/superpowers/specs/2026-05-14-maintain-width-on-rehydrate-design.md` — covers `MEM-1.6` through `MEM-1.9`.
