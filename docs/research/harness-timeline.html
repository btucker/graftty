Each harness owns its syntax

1. CaptureA prompt hook or the existing incremental transcript reader supplies a record.
2. DecodeCodexTimelinePlugin or ClaudeTimelinePlugin checks known envelopes and structured answers.
3. RetainShared parts retain authorship and presentation before the history text limit is applied. Authored input takes priority over generated details.
4. RenderThe shared SwiftUI view displays answers, commands, and session notices on Mac and mobile.

HarnessTimelinePlugin is a Swift protocol. A new adapter registers its runtime and envelope names, then implements its decoders. It can reuse existing presentation kinds without changing either client.

Prompt text and transcript records are separate inputs to the adapter. That distinction matters for Claude answers and synchronous Codex answers, which arrive through tool results rather than ordinary human prompt text.

What makes a reply safe to interpret

  • Authorship comes from the format. A provider's user role also carries peer reports, shell output, and generated context. Those records do not become orange human messages merely because of their role.
  • Question content survives the size limit. New captures decode first, then bound the structured fields. Existing complete wrappers are reinterpreted when saved history is projected.
  • Unknown data stays visible. Malformed answer JSON, incomplete human reply envelopes, unfamiliar tags, and inline or fenced examples retain their text.
  • Replies have stable identity. Native question results use the harness, session, and source record to derive an input ID. Rebuilding a cursor does not duplicate a captured reply.
  • Interruption closes a turn. A later agent response cannot merge across an interruption into the earlier running turn.
  • Notices retain the existing wire vocabulary. Optional presentation metadata distinguishes visible session notices from hidden generated context. Older clients can decode the existing source values.
Other data found in the histories

The inventory also includes typed image blocks, assistant reasoning blocks, ordinary tool calls and tool output, compaction records, API-request snapshots, retained transcript placeholders, and pasted HTML, JSX, XML, project files, and logs. These need different handling from user text envelopes. The existing assistant capture excludes reasoning and tool output. The new input decoder admits only recognized structured question results from tool output.

Claude's forked-skill-launch wrapper appeared in retained API snapshots rather than canonical user records in this sample. Its generated wrapper is recognized if delivered as prompt text. API snapshots are excluded from the canonical record counts to avoid manufacturing duplicate user events.

Repository instructions supplied as ordinary human text remain visible. This change does not infer that every XML-like tag or Markdown heading is generated context.
