# Connected project maps

Each repository gets one illustrated map spanning its local worktrees and folder headers. Each worktree has a task-related landmark; connecting terrain joins the rows. Main checkouts receive a root landmark inspired by the project avatar and purpose. The project icon remains a placeholder until that map is ready.

Settings → General → Worktree backgrounds enables the feature and selects Illustration, Animation, or Sketch. Disabling it hides sidebar artwork and the terminal gradient and cancels generation. Style, resolved Ghostty backdrop, and project avatar changes select separate caches. This revision uses a new map cache; earlier independent worktree images are not migrated into it.

## Project direction and generation

Before the first map, Graftty chooses a metaphor category and visual medium from bounded root-file names, README and manifest excerpts, and the resolved project avatar. Examples include a botanical paper-relief garden, a watercolor marina, or weather cartography. Codex can infer the direction from text and the avatar; Apple Foundation Models supplies a text-only fallback with extracted avatar colors. A stable workshop family is the final fallback. The direction is cached under `~/Library/Caches/Graftty/ProjectArtwork/v2`, keyed by repository path and avatar revision. Ordinary code edits and individual regeneration preserve it.

For each map generation, Graftty tries installed Codex through `codex app-server`, using its existing authentication and configured model. No separate API key is needed. The request uses a private ephemeral read-only thread in a temporary directory, with hooks, shell tools, and configured integrations disabled. It does not resume the user's conversation. Generated images count toward Codex usage. Startup has a 25-second deadline, image generation 180 seconds, and direction inference 60 seconds. Cancellation stops the subprocess without starting a fallback.

The map prompt supplies ordered regions, their vertical proportions, bounded task context, project direction, selected style, and exact resolved Ghostty backdrop. It requests one bold silhouette and distinct dominant color per landmark, with connecting terrain between them and no baked-in labels or interface. Each landmark belongs in the first 80 logical points of its region, with a 12-point transition at either end. Extra row height holds terrain. Model output is resized to the requested canvas, so exact landmark placement still depends on the provider following the prompt.

Missing Codex installations, unsupported capabilities, authentication errors, limits, and generation failures fall back to Apple's ImageCreator. Apple generates missing landmarks separately and assembles them with preserved landmarks. It cannot edit the whole reference map, so its connecting terrain may be less coherent. Foundation Models translates task context into a short subject description when available; ImageCreator receives that subject, project colors, and theme instructions. A shorter retry handles supported creation errors. Apple generation requires a compatible device and foreground application.

## Stable landmarks and readable rows

Reordering changes the map's region order. Graftty moves saved landmark pixels into those positions and supplies the result as a reference for new connecting terrain. It restores the original landmark interiors after generation; only the 12-point transitions at their edges can change. Existing slices remain visible during generation and the replacement fades in over 350 milliseconds, respecting Reduce Motion. Rapid updates are debounced and obsolete results discarded.

The map uses a fixed 320-point logical width, rendered at double resolution. Each row displays its corresponding slice at its original scale, anchored top-left. Narrow sidebars crop it; wider sidebars reveal the remainder and then the theme background. A right-edge fade softens that transition. The last visible region also fades at the bottom. Extra space below a slice fades into the theme rather than stretching the image. Window resizing does not request new model output.

Worktree regions reserve at least 80 points, with more height for running panes; folder headers reserve 44 points. Folder indentation affects labels, leaving the map's horizontal origin unchanged. Both sidebar modes use the same map column without spacing between its rows. When the project rail is hidden, repository disclosure groups contain contiguous map rows. Collapsed descendants keep their saved landmarks for reopening. Wrapped content can exceed a reserved region and reveal the theme background below it. Selected rows, attention badges, and drop indicators remain native overlays.

White labels and status text have compact translucent black backing behind the text itself. This does not alter the label's layout size and keeps most of the illustration visible. The map has no generated text gutter.

The selected worktree supplies two representative colors sampled from its first 80-point landmark area. A native gradient uses those colors behind the entire window, including all terminal panes. It starts at 36% opacity, reaches 22% at one-fifth of the height, and fades fully into the Ghostty background at 75%. This avoids enlarging raster artwork behind terminals.

For panes with artwork, a cloned Ghostty config makes the default terminal background transparent and clears any per-terminal background image. Explicit cell backgrounds and text remain opaque. The original config is restored when artwork is absent. Reloading a surface config can clear active Ghostty key tables or key sequences; preserving those would require a narrower renderer appearance API. Config reloads rebuild the clone and reapply it to affected panes, including follower-history rendering. No user config file changes. Applications that paint their own cell backgrounds can cover the gradient.

## Context, regeneration, and cache

The existing Claude and Codex UserPromptSubmit plugin hooks forward up to 4,000 characters of submitted text through the shared CLI hook message. New worktrees wait for that input. Existing worktrees can recover up to five recent user messages from the first pane's exact registered provider conversation, capped at 4,000 characters. Reads exclude assistant replies, tool output, and injected environment or Graftty messages. Bounded header and tail reads inspect at most 1 MiB each; opening user prompts supply context if the tail has none. Session-start hooks retry lookups that ran before registration.

Rows without task context receive quiet connecting terrain until a user prompt is available. Once created, a landmark remains stable across later prompts and launches. User context stays in memory and is not written to the artwork cache. Names are secondary hints; Graftty does not add repository paths to provider prompts, though user-authored excerpts can contain paths.

**Regenerate Background Image** refreshes the selected worktree's history and replaces its landmark while preserving the others. The selected sidebar image immediately blurs and dims; the terminal gradient dims. Success clears the pending appearance and crossfades the replacement. Failure retains the old map. If neither history nor captured context is available, Graftty retains the landmark and records a failure instead of replacing it with empty terrain. Main checkouts can regenerate from project context.

One serial worker processes project maps while Graftty is active. Deactivation cancels generation; activation resumes pending work. A failed project does not block other projects. Stale, creating, deleting, remote, and mobile worktrees are excluded. Hidden descendants remain registered so their landmarks survive folder collapse.

Each map cache file is an atomic JSON document under `~/Library/Caches/Graftty/WorktreeIcons/maps-v1`. It contains the complete PNG, saved landmark PNGs, dimensions, and row metadata, but no user prompt text. Its filename hashes project identity, avatar revision, style, and backdrop. Returning to a cached theme restores its corresponding map. Cached documents are bounded to 64 MiB and logical canvases to 32,000 points high.

## Findings

On September 16, 2026, the original generic prompt produced several nearly identical blue-green feather images. Graftty's logs also showed unsupported-language and person-identity errors for raw worktree names. The original queue treated these as terminal failures, leaving those worktrees without artwork.

A signed temporary app bundle on macOS 26.3 generated all six samples through the two-stage pipeline: `generate-icons`, `claude-notifications`, `graftty-crash`, `paging-through-scrollback`, `wf_ec05fbc1-baf-2`, and `research/nearshore`. Five names produced language-model descriptions. The `generate-icons` response failed structured decoding and used its red-panda fallback. The resulting images had visibly different subjects and were checked together in a rendered block preview.

The successful probe used the production generator source and an ad-hoc signed app bundle without additional entitlements. An earlier probe launched as a bare executable failed with `backgroundCreationForbidden`, even though `NSApplication.isActive` was true. Rendered previews use the production background component with sample pane rows. The latest full Graftty sidebar has not been visually verified in a running app.

A separate native rendering probe used three real host-managed Ghostty terminals over the production terminal backdrop. Its own view capture confirmed the continuous image, vertical fade, readable text, and opaque explicit cell backgrounds. Ghostty updates rendered pixel alpha on config changes but retains the native layer's original opacity flag, so Graftty also updates that flag when applying the per-pane config.

The context reader was checked against this worktree's registered Codex conversation without printing its prompt contents. That check caught and fixed enumeration of the managed Codex home's symlinked sessions directory. A signed Foundation Models probe using the generic name `task-123` produced a calendar with airplanes for a travel-planning request and a telescope for an astronomy request. One earlier astronomy attempt used the deterministic fallback, so context improves relevance without eliminating model failures.

The installed SDK exposes `ImageCreator` starting at macOS 15.4. Generation also requires Image Playground availability on the device. Apple requires image creation in the [foreground](https://developer.apple.com/documentation/imageplayground/imagecreator/error/backgroundcreationforbidden).

Apple announced `ImageCreator` deprecation in [WWDC26](https://developer.apple.com/videos/play/wwdc2026/375/), with generation moving to the Image Playground sheet. This spike demonstrates automatic generation on macOS 26.3. It does not establish a supported automatic-generation path for future macOS versions.

## Validation

On September 17, Codex CLI 0.154.0 advertised native image generation through `modelProvider/capabilities/read`. Both a standalone protocol probe and the production Swift client generated real images using existing authentication. The Swift request completed in 38 seconds, including its temporary thread and disabled integrations. Provider tests cover fallback and cancellation; a fake app-server checks isolation, early image events, failed/empty responses, unsupported capabilities, hung processes, and executable discovery. Live generation is deliberately excluded from the automated suite to avoid consuming Codex usage during tests.

A later three-task probe checked visual separation using the production Codex prompt and the resolved Ghostty theme. Notifications produced a yellow telephone, scrollback a teal boat feeding a paper scroll, and crash repair a purple rock formation with a blue channel. The images remained visibly different when rendered through the production sidebar overlay at a 350-by-112-point row size. The probe used representative task descriptions, not copied private conversations. Prompt tests verify stable independent directions, regeneration changes, and limiting the theme instructions to the selected accents without dimming the subject.

A project-direction probe used Graftty's actual avatar and bounded codebase summary. Codex chose an old-world tree nursery and grafting conservatory, then generated task-specific images for notifications, scrollback, and crash repair. Inspection caught correlated color and subject choices; their selection now uses independent seeds. Unit tests cover cached direction reuse, avatar changes during generation, cancellation, malformed inference, avatar readiness, and retaining the family through Apple fallback.

The targeted tests cover serial generation, cache reuse, name selection, failed requests, unavailable generation, invalid image data, removed requests, and cancellation during rapid focus changes. Context tests cover deferred generation, exact conversation matching, provider user-message parsing, bounded reads, legacy-image replacement, same-name isolation, and session-start retries. Preference tests cover persistence and cancellation/style cache behavior. Identity tests cover stable visual choices, language-model translation and fallback, bounded ImageCreator retries, and project-icon selection. Rendering tests check fixed map scale, label backing, palette sampling, and the terminal fade in light and dark themes. Native tests check config inheritance and layer opacity restoration. Thumbnail tests check retained resolution and aspect ratio. Run them with `scripts/swiftpm test --filter 'Worktree.*(Artwork|IconStore)|ProjectArtworkDirectionTests|CodexArtworkClientTests|AgentHookPromptTests|AgentPluginInstallerTests|NotificationMessageTests|WorktreeTerminalBackgroundTests'`.

Before the connected-map revision, a serial run passed 3,297 Swift Testing tests and 115 XCTest tests. One existing Codex-home locking test stalled while waiting for an exited fixture process; excluding that test allowed the run to finish, and the test passed separately in isolation. Native window rendering verifies that sidebar and terminal columns share one image coordinate system. A read-only check against the affected internships-web sessions confirmed that opening-prompt fallback recovered context for three previously skipped worktrees. Parallel runs encountered contention-sensitive failures in existing presence-storage, polling, RPC, and inbox-watcher tests; those groups passed in the serial run. Regeneration tests verify fresh context, preserving the displayed image on failure, discarding superseded results, retaining pending state across sidebar refreshes and focus changes, and loading replacement pixels from cache.

Build the app bundle with `scripts/bundle.sh` and open `.build/Graftty.app` to evaluate the sidebar and terminal backgrounds. Existing provider plugins already contain the required hooks; submitted-text forwarding uses the rebuilt bundled CLI.

A September 17 live Sketch probe using the resolved `#282c34` background and ANSI palette produced a visibly darker backdrop with muted gold/red accents after moving the background instruction first. Some light paper edges remained, so the native model still does not guarantee an exact backdrop match.

On September 18, the connected-map revision passed 57 targeted tests covering map composition, preserved pixels, cache reuse, serial project generation, cancellation, live prompt routing, folder visibility, context refresh, theme restoration, reference-image transport, and sidebar/terminal rendering.
