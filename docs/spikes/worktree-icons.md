# Automatic worktree artwork

This spike generates linked-worktree artwork through installed Codex, with Apple's Foundation Models and `ImageCreator` as the fallback. Generation waits for user-authored task context and runs automatically while Graftty is active. Main checkouts use their project's existing icon, enlarged and cropped, without calling a model. If a project has no icon, its main checkout retains the standard background.

For each uncached generation or manual regeneration, Graftty looks for Codex on the login shell's PATH or in the desktop app. It tries native image generation through `codex app-server` using the existing authentication and configured model. No separate authentication check or API key setup is required. Missing installations, unsupported versions, authentication errors, limits, invalid images, and generation failures fall back to Apple. Startup has a 25-second deadline; generation has a 180-second deadline. Cancellation stops the subprocess without starting a fallback.

Codex receives the bounded user-task context, worktree name, selected style, variation, and exact resolved Ghostty background and two selected accent colors. It chooses the subject and generates the image in one turn. Each worktree gets stable subject, silhouette, composition, and rendering directions derived from its name. These guide task-related metaphors toward different visual identities, including for worktrees with similar software tasks. Manual regeneration changes the directions. The prompt favors large recognizable shapes and a dominant color area over fine texture. It matches the backdrop to Ghostty, keeps the subject clearly lit, and leaves dimming and fading to the UI. It does not receive the entire shared theme palette or instructions to dim the whole scene. These choices encourage variety without guaranteeing that generated subjects will never resemble one another.

The Codex request uses a private ephemeral read-only thread in a temporary directory, with hooks, shell tools, and configured integrations disabled. It does not resume or steer the user's conversation. Generated images count toward Codex usage. Existing cached images remain until regeneration, a style change, or a theme change requires a replacement; prompt changes do not trigger a batch of paid generations.

Settings → General → Worktree backgrounds controls the feature. It defaults to enabled with Illustration; Animation and Sketch are also available. Turning it off hides both sidebar and terminal artwork and cancels generation. Changing style uses a separate cache and generates replacements from captured context or available history. Main checkouts continue to use their project icons.

Each worktree block displays one continuous image behind its heading and all its pane rows. The image fills and crops to the block without changing its dimensions. A theme-colored gradient covers most of the artwork behind the text on the left and reveals more on the right. The existing symbols, attention badges, selection tint, and drop outline remain in front. Drag previews use the same background.

The selected worktree also displays one image behind the entire terminal split layout. It starts at 36% opacity at the top, reaches 22% at one-fifth of the height, and fades completely into the configured Ghostty background by the vertical midpoint. Splitting or resizing panes reveals different portions of that shared image. Zooming a pane uses the same full-area backdrop. Main checkouts use the project icon here too.

For panes with artwork, a cloned Ghostty config makes the default terminal background transparent and clears any per-terminal background image. Explicit cell backgrounds and text remain opaque. The original config is restored when artwork is absent. Config reloads rebuild the clone and reapply it to affected panes, including follower-history rendering. No user config file is changed. Applications that paint their own cell backgrounds can cover the artwork.

For the Apple fallback on macOS 26 and later, an available on-device Foundation Models session translates the user's task and worktree name into a short English description of a physical subject. The structured response uses `@Generable`. User-authored context carries the task's meaning; the worktree name is a secondary hint. The name beneath `.worktrees` includes namespace components; other linked checkouts use their directory basename. Graftty does not add repository paths to either provider's prompt; user-authored excerpts may themselves contain paths.

The existing Claude and Codex `UserPromptSubmit` plugin hooks forward up to 4,000 characters of submitted text through the shared CLI hook message. New worktrees wait for that input. For existing worktrees, a background read matches the first pane's registered top-level provider session to its exact saved conversation and extracts up to five recent user messages, capped at 4,000 characters. It excludes assistant replies, tool results, and injected environment or Graftty messages. Missing or unreadable history leaves the worktree waiting for a prompt; it does not fall back to scraping terminal output. A session-start hook can retry a lookup that ran before the agent registered.

Once generated, an image stays stable across later prompts and launches. User context remains in memory for style changes and is not copied into the artwork cache. History reads inspect only the matched conversation, with bounded header and tail reads of at most 1 MiB each.

Right-click an enabled local linked worktree and choose **Regenerate Background Image** to replace it using refreshed user-message history and the selected style. If history is unavailable, the latest captured prompt supplies context. The current image immediately blurs and dims across the sidebar block and shared terminal background while regeneration is pending. Text remains clear. Success replaces the image; failure restores the old image’s clarity and can be retried from the same menu. Each manual regeneration changes the palette and composition and asks the prompt model for a fresh task-related metaphor, using randomized sampling and a different creative direction. The selected style stays the same. A small numeric variation marker is saved beside the PNG so future regenerations can vary the cached choices after relaunch. Main checkouts keep their project icons and do not offer generation.

For Apple generation, Ghostty's resolved background and ANSI colors guide the palette and lighting. Each worktree selects a pair of theme accents, with a dark backdrop for dark themes and soft daylight for light themes. The backdrop is the first image concept. Dark colors with low saturation are described as charcoal instead of saturated blue, and muted accents stay muted in the prompt. Apple's dark-theme prompts use positive low-light instructions without mentioning white. Color descriptions guide ImageCreator; they do not guarantee exact RGB matches. Theme changes generate matching replacements while preserving existing images until completion. Returning to a previous theme reuses its cached artwork.

The name selects a stable subject fallback, accent pair, and composition using SHA-256. ImageCreator receives the translated subject and these visual choices, without the raw name or conversation. If translation is unavailable, fails, or returns an unsuitable description, the name selects a familiar fallback subject such as a fox, lantern, or octopus. These choices improve variety but do not guarantee unique subjects or palettes for every pair of worktrees. Artwork and context are isolated by worktree path, including same-named worktrees in different repositories.

ImageCreator gets one retry with a shorter fallback description if it rejects the language, requests a person's identity, or reports a general creation failure. Cancellation and device unavailability do not trigger that retry. A worktree that still fails is skipped for the rest of the launch. If Codex fails and Apple is unavailable, generation stops until a manual retry or reconfiguration. App deactivation cancels generation, and activation resumes missing images. Stale, creating, and deleting worktrees are excluded. Remote and mobile rows do not use this cache.

The cache stores PNGs with a maximum edge of 512 pixels under `~/Library/Caches/Graftty/WorktreeIcons/v5/<style>/v2-<theme-color-hash>`, keyed by a SHA-256 hash of the worktree path. Images retain their aspect ratio. The cache survives relaunches. Images from the earlier theme-prompt cache and unthemed version 5 artwork remain visible until replacements using the corrected prompt are ready. For Illustration, version 4 artwork is also available as a placeholder.

## Findings

On September 16, 2026, the original generic prompt produced several nearly identical blue-green feather images. Graftty's logs also showed unsupported-language and person-identity errors for raw worktree names. The original queue treated these as terminal failures, leaving those worktrees without artwork.

A signed temporary app bundle on macOS 26.3 generated all six samples through the two-stage pipeline: `generate-icons`, `claude-notifications`, `graftty-crash`, `paging-through-scrollback`, `wf_ec05fbc1-baf-2`, and `research/nearshore`. Five names produced language-model descriptions. The `generate-icons` response failed structured decoding and used its red-panda fallback. The resulting images had visibly different subjects and were checked together in a rendered block preview.

The successful probe used the production generator source and an ad-hoc signed app bundle without additional entitlements. An earlier probe launched as a bare executable failed with `backgroundCreationForbidden`, even though `NSApplication.isActive` was true. Rendered previews use the production background component with sample pane rows. The latest full Graftty sidebar has not been visually verified in a running app.

A separate native rendering probe used three real host-managed Ghostty terminals over the production terminal backdrop. Its own view capture confirmed the continuous image, vertical fade, readable text, and opaque explicit cell backgrounds. Ghostty updates rendered pixel alpha on config changes but retains the native layer's original opacity flag, so Graftty also updates that flag when applying the per-pane config.

The context reader was checked against this worktree's registered Codex conversation without printing its prompt contents. That check caught and fixed enumeration of the managed Codex home's symlinked sessions directory. A signed Foundation Models probe using the generic name `task-123` produced a calendar with airplanes for a travel-planning request and a telescope for an astronomy request. One earlier astronomy attempt used the deterministic fallback, so context improves relevance without eliminating model failures.

The installed SDK exposes `ImageCreator` starting at macOS 15.4. Generation also requires Image Playground availability on the device. Apple requires image creation in the [foreground](https://developer.apple.com/documentation/imageplayground/imagecreator/error/backgroundcreationforbidden).

Apple announced `ImageCreator` deprecation in [WWDC26](https://developer.apple.com/videos/play/wwdc2026/375/), with generation moving to the Image Playground sheet. This spike demonstrates automatic generation on macOS 26.3. It does not establish a supported automatic-generation path for future macOS versions.

## Validation

On September 17, Codex CLI 0.154.0 advertised native image generation through `modelProvider/capabilities/read`. Both a standalone protocol probe and the production Swift client generated real images using existing authentication. The Swift request completed in 38 seconds, including its temporary thread and disabled integrations. Provider tests cover fallback and cancellation; a fake app-server checks isolation, early image events, failed/empty responses, unsupported capabilities, hung processes, and executable discovery. Live generation is deliberately excluded from the automated suite to avoid consuming Codex usage during tests.

A later three-task probe checked visual separation using the production Codex prompt and the resolved Ghostty theme. Notifications produced a yellow telephone, scrollback a teal boat feeding a paper scroll, and crash repair a purple rock formation with a blue channel. The images remained visibly different when rendered through the production sidebar overlay at a 350-by-112-point row size. The probe used representative task descriptions, not copied private conversations. Prompt tests verify stable independent directions, regeneration changes, and limiting the theme instructions to the selected accents without dimming the subject.

The targeted tests cover serial generation, cache reuse, name selection, failed requests, unavailable generation, invalid image data, removed requests, and cancellation during rapid focus changes. Context tests cover deferred generation, exact conversation matching, provider user-message parsing, bounded reads, legacy-image replacement, same-name isolation, and session-start retries. Preference tests cover persistence and cancellation/style cache behavior. Identity tests cover stable visual choices, language-model translation and fallback, bounded ImageCreator retries, and project-icon selection. Rendering tests check fixed block dimensions, the leading text scrim, and the terminal fade in light and dark themes. Native tests check config inheritance and layer opacity restoration. Thumbnail tests check retained resolution and aspect ratio. Run them with `scripts/swiftpm test --filter 'Worktree.*(Artwork|IconStore)|AgentHookPromptTests|AgentPluginInstallerTests|NotificationMessageTests|WorktreeTerminalBackgroundTests'`.

The latest full run reported 11 timing-related issues among 3,253 Swift Testing tests, in existing presence-storage, polling, RPC, and inbox-watcher tests. All affected groups passed when rerun alongside the artwork and drag-marker tests, totaling 110 tests. Regeneration tests verify fresh context, preserving the displayed image on failure, discarding superseded generation results, and loading the replacement pixels from cache. The XCTest portion of the full run passed all 115 tests.

Build the app bundle with `scripts/bundle.sh` and open `.build/Graftty.app` to evaluate the sidebar and terminal backgrounds. Existing provider plugins already contain the required hooks; submitted-text forwarding uses the rebuilt bundled CLI.

A September 17 live Sketch probe using the resolved `#282c34` background and ANSI palette produced a visibly darker backdrop with muted gold/red accents after moving the background instruction first. Some light paper edges remained, so the native model still does not guarantee an exact backdrop match.
