Let the agent catch you up

The deck stays. The per-kind answer widgets (Allow, option buttons, Approve) are dropped. When you come back to an ask, the first thing you usually do is ask the agent to explain it again, so Graftty does that step for you. Answering then happens in the agent's own terminal, where the harness already handles it well.

Graftty never draws a harness's answer UI. It shows plain text the agent wrote and sends plain text to the agent, so it works the same for Claude, Codex, and any later harness.

Two layers of catch-up

1 · Written when it asks (instant)When an agent reports a need, the skill also asks for a short catch-up written for someone who has forgotten the worktree: what's going on, the choices, and what the agent recommends. It's written while the context is fresh, and it's on the card with no wait.
2 · Explain more, always availableEvery card has Explain more. It sends a standard catch-up prompt into the agent's input and opens its terminal. The terminal opens straight away and the agent explains in it, then asks again. You answer right there, or keep the conversation going.
Answers stay in the terminalEvery card offers Explain more, Open terminal, Later, and Dismiss. Graftty never sends an answer on your behalf, so it can't send a wrong one.

The prompt Explain more sends

It's short, and the same for every harness. Ending with the question again means the terminal finishes where you answer. Users could edit it in Settings.

Catch me up before I answer. I've lost the context for this worktree.
In under 150 words: what you're working on and why, what you've found,
the choices in front of me and what each costs, and what you recommend.
Then ask your question again.

When the agent is in a modal prompt

While a harness shows an option or permission dialog, typed text doesn't reach the agent as a message. So "Explain more" also goes into the harness's own dialog:

The agent always offers itThe graftty skill tells agents that every question with options includes Explain more as one of its options. Claude's AskUserQuestion dialog then has it built in, and choosing it in the terminal gets the same explanation. Graftty never has to type into a dialog.
The card button opens the dialogWhen the hooks report a dialog is open, the card's Explain more becomes "Explain more in terminal" and opens the pane, where that option is waiting.
Permission dialogsTheir options are fixed, so the card's catch-up has to cover them. Declining with an instruction ("explain why first") still works in the terminal.
