One project across hosts

Latest pass, with your answers on folders, waking hosts and project order. Rows are a name plus one status line, temporary worktrees are a flat list by recent activity, and port chips move to the Mac header.

Mockups are drawn in HTML, and nothing has been built. The Mac ones follow your screenshot. iPhone and iPad follow the code rather than a screenshot, so they're rougher. Host names, worktrees and report text are made up.

What changed in this version

  • Folders only in Pinned Agents. Temporary worktrees are flat and show their full name, such as spikes/old-relay. Pinned folders with the same name merge across hosts.
  • Hosts wake only when you need them, such as opening one of their worktrees. Sleeping hosts' rows stay visible and dim, so there's something to open. See "Sleeping hosts".
  • Project order syncs too. See "Project order".
  • No panes in the sidebar. Each row shows one status line. Your question was whether we've outgrown them, and I think we have: the tabs already show them, and few things are unique to the rows. Those are listed under "What pane rows do today" below.
  • No manual order for temporary worktrees. The sort control goes away, on single-host projects too.
  • Pinned Agents always name the host when the project is on more than one. Temporary rows only name it when names clash.
  • Pinned order is shared across hosts. It's the same on every device, and you can drag across hosts. You confirmed this approach. See "Pinned order that follows you".
  • Port chips sit in the Mac header for the selected worktree.

Pinned order that follows you

Every device shows the same pinned order, and you can drag across hosts. Hosts never need to talk to each other. Each pinned worktree stores its own rank on the host that owns it, and each device merges rows by rank. Only the dragged row changes, on its own host.

Numbers are for illustration. The real rank would be a fractional index, a sortable string that always leaves room for a row between two others.

How it holds up

  • Host asleep: its rows stay in place, dim. Host otherwise offline: its rows disappear and return to the same place when it's back.
  • Two devices drag the same row: the last write to that host wins.
  • Two rows land on the same rank: ties break on host and path, so every device agrees.
  • Older host: it sends no rank, so its pins sit last in its own order and can't be dragged across hosts.

Details

  • First run: ranks come from each host's current order, so existing pins interleave until you drag them once.
  • Default checkouts: still first, as today (LAYOUT-2.103), sorted by host name so devices agree.
  • Replaces: pinned moves use the rank instead of moveWorktree, and the cross-host drop rejection (LAYOUT-2.61) no longer applies to pins.

What I ruled out

  • A shared list copied to every host: edits made while a host is offline have to be merged later, and hosts would need a way to reach each other.
  • iCloud or similar: doesn't reach Linux hosts.
  • A list on each device: doesn't sync.

Project order

It works like pinned order, with ranks stored on hosts and merged by each device. The difference is that a project can live on several hosts, so each drag goes to all of them and the newest change wins.

SituationWhat happens
You drag a projectThe new rank and time go to every reachable host with that project. Sleeping hosts aren't woken for it.
A host missed the dragIts value is older, so it loses. A device that sees both copies the newer value to it.
Every host for the project is asleepThe drag wakes the last-used host, because it needs somewhere to write. If that fails, the project returns to its old place.
First runRanks come from each host's current order, so projects interleave until you drag them.
Older hostIt sends no rank. Its projects sit last in its own order, and moving one uses today's request.

When a worktree is open

The host joins the worktree's identity wherever it's shown, in the same quiet style as the project name. Remote worktrees always show it. "This Mac" only appears when the project also lives on another host, so people with one machine never see it.

Sleeping hosts

Background connections never wake a host. Anything that needs the host does, such as opening a worktree, tapping its question, creating a worktree on it or dragging its pinned row.
