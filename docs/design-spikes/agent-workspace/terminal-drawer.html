Interactive layout study. Only the Terminal disclosure works; other controls and terminal output are illustrative. Provider icons identify Claude and Codex.

Collapsed

The bar reads >_ Terminal 2. The count means open shell sessions, not notifications. It spans the worktree canvas, below any agent splits.

With no sessions, show >_ Terminal. Opening it offers New terminal. Keep the label visible so the feature is discoverable.

Expanded

The same bar becomes the drawer header. Shell tabs, a new-terminal action, and the terminal appear below it. Hide collapses the drawer and leaves the shells running.

Remember height and visibility per worktree. Opening focuses the last-used shell; hiding returns focus to the previous agent.

Keep the control small, but findable

Use a 34-point bar on Mac and a touch-sized control on mobile. Offer a menu action and a configurable shortcut. Dragging the divider resizes an open drawer; dragging is never the only way to reveal it.

A hidden terminal can show a specific attention label such as "Build failed" without opening itself or taking focus. Ordinary output does not produce an attention badge.

Mobile

Place the Terminal control above the keyboard accessory row and safe area. On iPhone it opens a full-height terminal, with Back to agent returning to the prior view. On a roomy iPad it can expand below the agent.

The choice to test

A full-width bar is easy to find but costs a little vertical space even when closed. A small corner button costs less space but is easier to miss. Start with the labeled bar and test it in a short window.

Proposal only. The bar responds to click and keyboard activation. Focus restoration, process lifetime, resizing, and native keyboard placement are described behaviors, not implemented in this HTML study. macOS design reference.
