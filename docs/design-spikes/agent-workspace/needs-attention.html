What actually needs you?

A “1” says there is something to clear. It does not say who is waiting, what they need, or whether you need to do anything at all.

The change beneath all three options

“Needs you” means a current question, permission prompt, or explicit review request addressed to the person. An ordinary completed turn is an update. A child finishing is the parent agent’s responsibility.

Keep the hierarchy you chose

Select the whole worktree. Keep uppercase worktree names with PR and Git status on the same line. Indent agents. Use live terminal titles in tabs and sidebar, with provider icons only in tabs.

Approved

A · Put the reason beside the agent

Reuse the amber waiting glyph in the agent row and tab. Add one short question below the agent title. Remove numeric attention badges everywhere.

Tradeoff: Easy to understand without opening anything. A request makes its worktree taller; long questions need a two-line limit.

Lowest visual weight

B · Keep the list compact

Only the shared status glyph changes in the sidebar. The question appears above terminal content when that worktree is opened. No badges and no extra sidebar line.

Tradeoff: Preserves a steady list, but you must open the worktree to learn why it needs you. Glyph meaning has to be learned.

For many worktrees

C · Give requests their own filter

An optional Needs you filter shows only worktrees with a current human request. It preserves worktree order and whole-worktree selection. No duplicated inbox or counters.

Tradeoff: Useful when requests are buried across projects. Adds a mode to navigation; it can hide work you were just looking at.

Make the signal trustworthy first

Removing the number alone would leave the same false alarm behind a different icon. These distinctions should drive both tabs and sidebar.

My recommendation

Start with A. The actual question earns the extra line; routine recaps do not. Reuse the same status glyph in the tab, and reveal the full request in the active agent area.

Keep worktrees in their familiar order. If agents are folded away, show a short “Input requested” summary on the worktree, rather than bringing back a count.

On iPhone, choosing a worktree preserves its remembered tab. A separate “Go to question” action reveals the requesting agent. New requests never steal focus.

Use C later if the number of active worktrees makes requests hard to find. It filters existing worktrees rather than creating a second inbox.

Should a finished update ever ask for your attention unless the agent explicitly requests a review?

I would default to no. Keep it in Context and the session, without making you clear it.
