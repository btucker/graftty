  • ALocation line, 11 pt secondary. Emoji, worktree name, then PR number and Git counts on the right. ↑0+ means nothing ahead but uncommitted changes present. Zero counts dim instead of disappearing, so the column never jumps.
  • BTask lines, 13 pt primary. One line per agent, in tab order. The task title is the only distinguishing label. Agents that share a worktree are told apart by what they are doing, not by which provider runs them.

Glyphs are drawn approximations of the SF Symbols in AgentStatusBadge. The proposed arc needs a new signal: time since the agent's terminal last emitted output. That is observable by Graftty. It is not proof the model is thinking, and a long silent tool call will show a plain ring.

Decisions and concerns

  1. The location line is never selected or tinted. In the screenshot that prompted this, rows mixed worktree selection, agent selection, disclosure, and badges. Here the worktree line is a passive label and every clickable row is an agent. That removes the disclosure triangle and the nested indent, and it makes the multi-agent case read as a short list under a heading.
  2. Status gets a column, not a badge. The glyph sits in the emoji column on task lines, so status scans as one vertical stripe down the left edge. Only waiting and failed are amber. Rows are not reordered by status, because worktree position is part of how people recognize them.
  3. Honest activity needs a new signal, and it should land in both places at once. Today the ring means an assignment exists. The proposed arc means recent terminal output. If that signal is not built, the ring alone is still truthful, and the sidebar should ship with exactly what the tabs show. Concern: five or more spinning arcs at once could feel busy. A cap on concurrent animation, or animating only the selected worktree, is worth testing.
