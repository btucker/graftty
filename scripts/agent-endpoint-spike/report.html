Rendering assertions

  • Logical text survives reflow in order.
  • Viewport and selection follow the promised anchor behavior.
  • Only the owner changes the authoritative PTY grid.
  • Stale pages and revisions cannot replace current state.
  • Return to live reaches the newest content.

Seeded sequence runner

  • Choose actions only when their preconditions hold.
  • Use named barriers instead of completion sleeps.
  • Save the seed, event trace, and client versions.
  • Capture renderer cells and screenshots on failure.
  • Shrink a failure into a short regression test.

Messaging gets an observable receipt

Production team send + nonce→Durable inbox + native delivery→Nonce in recipient model request→Scripted tool reply

Run every provider pairing. Repeat while idle, streaming, awaiting approval, restarting, and switching display owners. A successful send alone does not establish that the agent received the context.

Nonce observation and scripted replies are proposed. The current fixture emits text only; tool-call and tool-result handling must be added.

The main trap is the oracle

Claude's redraw split a visible completion marker across cursor commands. Raw byte searches failed even though its native session recorded the complete response. Full tests must inspect renderer cells and logical anchors; screenshots and PTY logs are supporting evidence.

Recommendation: build a small native Mac/mobile suite over the scripted endpoint, then explore more action orderings with deterministic seeds. Keep a small live-provider smoke test for protocol and authentication drift.
